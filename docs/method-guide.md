# About CasePath

[Start the local workbench](setup.md), then open [About CasePath](../casepath/method.html). The page links to a real family-home claim, its What if control, the 150-claim data browser, and the research results.

## Follow one claim

1. Open the [family-home claim](../casepath/index.html#claim=clm_f69b1747447bc221&what_if=family_home). Read the customer's message and the two original notices in Sources.
2. Select **Review claim**. The narrative names each check and links it to a source. The saved canvas shows different end dates and asks when each notice arrived.
3. Find **What this claim needs**. The notice copies are held, not reviewed; proof of receipt is needed now.
4. Select **What if** beside family-home service and set it false. The spouse-notice route leaves the request in the sandbox. Exit to return to the saved assessment.
5. Select **Draft request**. Read or edit the saved proposal before copying or exporting it. Its status is **Draft, not sent**.

The earlier authored repair example is retained as [downloadable data](../casepath/assets/method-guide-data.json), including 45 executed states and source hashes. It is a teaching record, not a claim in the workbench or a measured benchmark result. Its [generator](../examples/build_method_guide.py) and [controller](../casepath-api/casepath_api/obligation_control/obligation_control_v1.py) remain in the repository for reproduction.

## Read the evidence correctly

The workbench's deterministic assessment is product behavior. The paper's Study A and Study B use different populations, implementations, and endpoints. Enable **Reviewer mode** on a claim to see each displayed object's provenance class and the paper's correspondence table. [Research evidence](research-evidence.md) gives measured results and limits.
