# Selection-time full-head snapshot admission

Read-only verdict against the reviewed b297 source: feasible without a backend change, provided a dedicated full-snapshot head validator enforces the conditions below. Do not synthesize a replay envelope/provenance and call that independent verification.

The actual server `store.snapshot(after=0)` and `store.replay(through=head.revision)` both execute the same `_replay` over the entire saved journal. That reducer validates every event/command hash, sequence, previous event, expected state, resulting state, and persisted source. `with_history=True` additionally retains each intermediate state; it does not make the final state more authoritative. Both return the same complete head state/events and `reference_replay_start`. API projection uses the same function. Snapshot mode is `saved`; replay mode/provenance/current_head are replay-specific envelope metadata.

Required frontend equivalence conditions:

1. Issue the real atomic `/snapshot?after=0` at selection, then call `readSnapshot(response,id,null,true)`. Require the actual supported saved-head envelope and a positive safe revision. Null previous cursor is essential: `acceptEvents` must see every event1..N, not an accepted suffix. Its gap/duplicate/tail checks reject truncated or partial history.
2. Require snapshot state/current revision and state hash to equal the already checked revision-zero reply's pinned current-head tuple. Explicitly require raw `current_event_sha256`, `cursor_sha256`, state `last_event_sha256`, final event hash and opening current-event hash all to agree. `readSnapshot` does not itself compare raw `current_event_sha256`.
3. Require snapshot `replay_start` to agree canonically with the real revision-zero reply's start, and require a non-null `checkedReferenceReplayStart(start,incoming)`. Retain current-run profile/run/source-artifact identity, accepted process.prepared event, complete reference outcome and settled-run checks. Preserve head source-roster/rule-set binding used by `checkedOperationBinding`.
4. Retain exact original binding identity and every original descriptor from the checked opening; additional admitted supplementary sources may exist at the head. Do not confuse profile supplement hashes with the complete current roster or corpus claim binding with the derived original-binding wrapper.
5. Frontend `readSnapshot`/`acceptEvents` check sequence and tail identity, not every event body hash/previous-event link. The server validates those for both endpoint paths. If the new helper claims client chain coverage, explicitly walk the existing event hash links; the existing `checkedSavedSnapshot` helper also checks history links, source text/citations and graph structure without any new source GET. Do not claim these stronger checks ran merely because `acceptEvents` passed.
6. Replay's `provenance` and `current_head` mirror are generated by `_provenance(state)` from the same verified state; snapshot does not carry this separate mirror. Validate actual state/source/binding identities and existing reference-start/operation bindings directly. Do not fabricate mirrored fields from the same object and present the equality as new provenance evidence. If a real response supplies provenance fields, contradictory fields must still reject.

Only then set the same session's verified journal, reference start, reference as-of, operation binding and sanitized planned process. Do not paint the head state or borrow its accepted facts/completions into prefix0. Maintain stale epoch/route/abort, hidden, inspection and modal gates. Snapshot rejection/unavailability may fall back to the existing head-replay path; no incomplete or mismatched snapshot may be repaired, relabeled or admitted. A concurrent head advance must not be merged into the opening's pinned tuple.

This removes a client-side serial head dependency, changing that part of the floor from two serial read latencies to the slower independent read. It cannot meet a3s real first landing if a necessary response itself takes4.5s before its first byte.

No implementation, tests, engine/browser run or network request was made for this review.
