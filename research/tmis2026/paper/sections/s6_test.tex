\section{Confirmatory test (Study 3)}
\label{sec:test}

We tested \casepath at a frozen commit against single-prompt, self-consistency, explicit-semantics and ReAct baselines and a frontier single prompt, on sealed data and under a plan fixed in advance. We call this test Study~3. It has two regimes, theft and tenancy, each with its own data, workflow and measures. H1 to H3 were confirmed, H4 was not, and H5 was therefore not tested. H3 was tested only because we changed the order of the hypotheses shortly before the freeze (Section~\ref{sec:test-hypotheses}).

\subsection{Data and freeze}
\label{sec:test-data}

The test data, \texttt{fresh2/}, were built and sealed before any design ran on them (Appendix~\ref{app:datasets}). Theft has \sthreeStories{} new stories: \sthreePairsChanged{} changed-fact pairs and \sthreePairsUnresolved{} unresolved-fact pairs from \sthreeTexts{} texts. Tenancy has \sthreeClaims{} new claims in \sthreeFamilies{} families, half in English and half in Swiss Standard German, with \sthreeAttachments{} attachments. Each tenancy dispute has a defining event, such as receiving a written rent-increase notification. The plan defines three subsets from the reference: \sthreeClaimsDenied{} \emph{denied-event} claims, which say the defining event has not happened; \sthreeClaimsOpenEvent{} \emph{open-event} claims, which leave it open; and \sthreeClaimsOrdinary{} \emph{ordinary} claims, of which \sthreeClaimsOpenBranch{} leave another fact open. The test set was designed to include the denied- and open-event claims.

Three limits apply to every result below. The tenancy references are produced by the engine \casepath implements, under a silence clause that we wrote and that every design receives. One model wrote every text, and a model of the same family checked them blind. The texts have 77--320 words, so \casepath's paths for long files (Section~\ref{sec:pipeline}) were never exercised.

An AI agent session wrote the texts from a brief that held only the data design; it could read the repository, including the product's prompts and development results, so knowledge of the product may have shaped the texts in ways no check here can detect (Appendix~\ref{app:genai}). The session that directed development, drafted the plan and chose the open rule had written the test set's design and read its description and counts (\texttt{fresh2/\allowbreak{}README.md}), not its texts. Before the freeze, only the writing session and the blind-check sessions read the texts.

Development used the Study~1 data, \texttt{fresh/} and \sthreeProbeClaims{} probe claims whose defining event is denied or open; the probe was written knowing the test set's design but not its texts. Development effort was one-sided: \casepath was revised over three studies on development data. Rules in context reuses texts committed for Study~1, with additions written and partly changed during Study~2's development. Model executes rules and ReAct were first committed during the product's development and run on development data before the freeze; Self-consistency samples Rules in context. No comparator text changed after 19:10 on 10~November (Appendix~\ref{app:dev-study3}).

The open rule (Section~\ref{sec:configuration}) was set after the probe, before the freeze and before any design read a sealed datum. An independent AI review session of the product's code found that a single ``not stated'' let a presumption override a doubt two readings had quoted; the directing author then chose the rule \texttt{any}, overruling a criterion on wrong holds that the author had set earlier. The system under test is the product at commit \texttt{6a72159c}, whose source-tree hash the parity command gave for every product run. At the time of writing, the product's owners have not confirmed the merge of this commit. Table~\ref{tab:s3-timeline} gives the dates.

The measures are Study~2's, computed by the same functions (Supplement, Section~\ref{S-app:study2}). In tenancy, \emph{strict unsafe errors per claim} count unnecessary requests, missed and handed-over required documents, premature requests and silent skips; \emph{all deviations per claim} add both kinds of wrong hold, so that a design cannot look good by holding. In theft, \emph{wrong + missed changes per pair} count the document changes between the two texts of a changed-fact pair that are wrong or missing; unresolved-fact pairs count premature requests and pairs left otherwise unchanged.

\subsection{Hypotheses}
\label{sec:test-hypotheses}

The plan states \sthreeHypotheses{} hypotheses in a fixed order: H1 theft and H2 tenancy against Rules in context on the same model; H3 tenancy against Rules in context on the frontier model; H4 theft against each of Self-consistency, Model executes rules and ReAct, all three required; H5 theft non-inferiority to Rules in context on the frontier model, margin \sthreeHFiveMargin. Each is tested at the \sthreeAlpha{} level only if all before it were confirmed. H1 to H4 use exact two-sided sign-flip tests over clusters, the \sthreeTheftClusters{} changed facts and the \sthreeTenancyClusters{} families, and a hypothesis of fewer errors also needs the difference to favour \casepath; with \sthreeTheftClusters{} clusters the smallest attainable $p$ is \sthreeMinPTheft. H5 uses a paired cluster-bootstrap non-inferiority test.

We changed this order 38 minutes before the freeze, and H3 was tested only because of the change. In the plan's final draft (21:26 on 10 November) the tenancy contrast against the frontier model came fifth, after theft against every prior-work strategy and theft against the frontier model; in the first draft (19:17) it came third, as a non-inferiority test. At 21:51 we moved it to third place (commit 482873e3). The plan's text then said that the contrasts development supported most strongly come first. The work log, written after the run, names the comparison with ReAct as the weakest on development data, where ReAct had run once on two theft stories; for the tenancy contrast, the probe had shown \casepath with 2.2 unsafe errors per denied-event claim against 6.0--6.6 for the single prompts. No design or scorer had then touched the sealed data, and the frontier-model runs that the commit adds used development data only. Under the order of 21:26, the prior-work hypothesis would have been tested third and would have failed as it did, the tenancy contrast against the frontier model would not have been tested, and only H1 and H2 would have been confirmed. H3's confirmation therefore depends on an ordering decision made on development evidence shortly before the freeze (Appendix~\ref{app:dev-study3}).

\paragraph{H1, confirmed}
On theft, with the same model and the same rules, \casepath made \sthreeHOneA{} wrong + missed changes per pair against \sthreeHOneB{} for Rules in context ($p\sthreeHOnePeq$). The theft rules had been reviewed for execution by editors who knew the test conditions (Section~\ref{sec:history}). Against Rules in context with the original rules the difference remained large on the same model (\sthreeSecFourCA{} against \sthreeSecFourCB, $p\sthreeSecFourCPeq$) and was small on the frontier model (\sthreeSecFourBA{} against \sthreeSecFourBB), the best single prompt on theft; both are secondary contrasts.

\paragraph{H2 and H3, confirmed}
On tenancy, \casepath made \sthreeHTwoA{} strict unsafe errors per claim against \sthreeHTwoB{} for the same model ($p\sthreeHTwoPeq$) and \sthreeHThreeB{} for the frontier model ($p\sthreeHThreePeq$). As the plan predicted, most of the difference lies in the \sthreeClaimsDeniedOpen{} denied- and open-event claims: \sthreeHTwoDeniedOpenA{} errors per claim against \sthreeHTwoDeniedOpenB{} and \sthreeHThreeDeniedOpenB. On the \sthreeClaimsOrdinary{} ordinary claims the values were \sthreeHTwoOrdinaryA{} against \sthreeHTwoOrdinaryB{} and \sthreeHThreeOrdinaryB; the difference from the frontier model was not significant ($p\sthreeHThreeOrdinaryPeq$), and that from the same model had $p\sthreeHTwoOrdinaryPeq$, which the plan did not predict. These subset values are family means and descriptive; per-claim means differ in the second decimal (Table~\ref{tab:s3-subsets}).

\paragraph{H4, not confirmed, and H5, not tested}
H4 required fewer theft errors than each of three prior-work strategies, and it failed. \casepath made fewer than Model executes rules (\sthreeHFourMERA{} against \sthreeHFourMERB, $p\sthreeHFourMERPeq$) and ReAct (\sthreeHFourReactA{} against \sthreeHFourReactB, $p\sthreeHFourReactPeq$), but against Self-consistency (\sthreeHFourSCA{} against \sthreeHFourSCB) the test gave $p\sthreeHFourSCPeq$; \casepath had fewer errors on \sthreePostSCFavourCasePath{} changed facts and more on \sthreePostSCFavourSelfCons{} (post hoc; Appendix~\ref{app:rob-study3}). The registered bootstrap interval excludes zero, but with nine clusters it is too narrow. The registered exact test gives each of the nine differences a random sign and counts how often the sum is as far from zero as observed; because the differences are unequal in size, such sums are not rare. The interval obtained by inverting this test includes zero (Table~\ref{tab:s3-intervals}). With the eight stories as clusters, a sensitivity added after review, $p=\sthreeRFiveHFourSCStoriesP$; it changes no status. So H5 was not tested: \casepath made \sthreeHFiveA{} errors per pair against \sthreeHFiveB{} for the frontier model with the same rules.

\paragraph{Open facts and holds}
\casepath held almost every document the engine's reference holds (Table~\ref{tab:s3-open}). On theft it left \sthreeCasePathThOpenUnchanged\% of unresolved-fact pairs otherwise unchanged, against \sthreeRicThOpenUnchanged--\sthreeReactThOpenUnchanged\% for every design from prior work with the reviewed rules. On tenancy it held \sthreeCasePathTenCorrectHold\% of the documents the reference holds, against \sthreeRicTenCorrectHold\% and \sthreeRicFrontierTenCorrectHold\% for the single prompts, and more that the reference neither requires nor holds: \sthreeCasePathTenSpurHold{} per claim against \sthreeRicTenSpurHold{} and \sthreeRicFrontierTenSpurHold, most on denied-event claims, where the defining event stayed unresolved. Counting wrong holds as errors, \casepath made \sthreeCasePathTenAllDev{} deviations per claim, against \sthreeRicTenAllDev{} ($p\sthreeSecThreeAPeq$) and \sthreeRicFrontierTenAllDev{} ($p\sthreeSecThreeBPeq$). Two-valued execution of \casepath's own readings made \sthreeTwoValFalseTenStrict{} strict unsafe errors per claim with unresolved taken as false and \sthreeTwoValTrueTenStrict{} with unresolved taken as true, against \sthreeCasePathTenStrict.

\paragraph{The checklist-only setting}
Dropping the agents that cannot decide the checklist, the brief, the process builder and the result checker, showed no detectable difference in errors: \sthreeChecklistTenStrict{} against \sthreeCasePathTenStrict{} strict unsafe errors per claim ($p\sthreeSecFiveAPeq$) and \sthreeChecklistThErrors{} against \sthreeCasePathThErrors{} wrong + missed changes per pair ($p\sthreeSecFiveCPeq$). No need added by an agent entered a scored checklist. The two settings share cached responses (\sthreeSharedTenCallShare\% of the full product's calls on tenancy, \sthreeSharedThCallShare\% on theft), so this is no independent repetition.

\paragraph{Cost and time}
Per tenancy claim and theft text, the full product costs USD~\sthreeCasePathTenCost{} and \sthreeCasePathThCost, checklist only \sthreeChecklistTenCost{} and \sthreeChecklistThCost, and the frontier single prompt \sthreeRicFrontierTenCost{} and \sthreeRicFrontierThCost: the full product costs \sthreeCasePathTenRatio{} (tenancy) and \sthreeCasePathThRatio{} (theft) times the frontier single prompt. Measured after review, a full case-run took a median of \sthreeRTenCasePathTenMedian{} and \sthreeRTenCasePathThMedian~s, checklist only \sthreeRTenChecklistTenMedian{} and \sthreeRTenChecklistThMedian~s, with \sthreeRunWorkersLater{} case-runs in parallel and some calls cached; the single prompt's one call took \sthreeRTenRicTenMedian{} and \sthreeRTenRicThMedian~s on the cost-efficient model and \sthreeRTenRicFrontierTenMedian{} and \sthreeRTenRicFrontierThMedian~s on the frontier model (Table~\ref{tab:s3-time}). We did not measure a handler's time, so we cannot set these times against it. Figure~\ref{fig:cost} in Appendix~\ref{app:robustness} sets each design's errors against its cost.
