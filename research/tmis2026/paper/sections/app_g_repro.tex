\subsection{Reproducing Study 3}
\label{app:release-reproduce}

Two steps reproduce Study~3's tables and figure from the stored outputs, without model calls. From \texttt{research/\allowbreak{}tmis2026/}:
\begin{lstlisting}
python3 analysis/study3.py --data fresh2 --label confirm
python3 analysis/make_numbers_study3.py && python3 analysis/fig_s6.py
\end{lstlisting}
The first command scores every stored checklist and runs every test of the analysis plan; it reads the data only through the guard of Appendix~\ref{app:data-fresh2} and refuses to run in a process that has a model client loaded. It reproduces the stored results file (\texttt{analysis/\allowbreak{}study3\_results\_fresh2\_confirm.json} and \texttt{.md}) byte for byte. The second line writes the number macros and the figure of Section~\ref{sec:test}. The numbers of Studies 1 and 2 are recomputed in the same way by \texttt{analysis/\allowbreak{}verify\_paper.py}, after the Study~1 response cache is unpacked, with the model client's budget set to zero.

One command re-runs Study~3 with model calls (\texttt{harness/\allowbreak{}study3/\allowbreak{}README.md}):
\begin{lstlisting}
CASEPATH_PRODUCT=<product worktree at 6a72159c> <venv>/bin/python harness/study3/run_all.py --data fresh2 --label <new label> --k 3
\end{lstlisting}
It first runs four checks: the plan is committed unmodified, the product is at the tested commit with the expected parity hash and settings, the tenancy templates have the recorded hash, and the converted workflows agree with the reference engines. With the stored response cache in place, every call is answered from the cache. With an empty cache, the calls are made again, and their answers can differ from the stored ones because the models are not deterministic.

\paragraph{Cost}
The ledgers record each model call of Study~3 with its cost: USD~\sthreeSpendTotal{} for the run, \sthreeSpendLuna{} on the cost-efficient model and \sthreeSpendTerra{} on the frontier model (Appendix~\ref{app:dev-study3}). The run log (\texttt{runs/\allowbreak{}study3/\allowbreak{}confirm/\allowbreak{}RUNLOG.jsonl}) does not record all of this spend and is not the source of these figures. A full re-run with an empty cache makes the same calls; the cost of each design per case is given in Section~\ref{sec:test}.

\subsection{What is not released, and why}
\label{app:release-not}

The insurer's process catalogue, its Knowledge and its case files are not released: they belong to the insurer, and the case files are real claims. The expert study's records leave the insurer only as the pre-registered pseudonymous export, which holds identifiers, statuses, counts, relative times and randomised labels, and no case content (Appendix~\ref{app:protocol}). Its content export, with item texts, notes and the passages behind the insurer's requests, stays with the insurer.

\subsection{Use of generative AI}
\label{app:genai}

\paragraph{Models as objects of study}
The evaluated models, \texttt{gpt-6-luna} and \texttt{gpt-6.1-terra}, are the objects of study: they read the files inside \casepath and answer in every other design. Study~1 also re-scored the recorded predictions of \texttt{gpt-5.6-terra} from the original study. In the original study a language model extracted the theft rules and their conditions from the source passages, and the theft references derive from a contract built by an agent; Study~2 tested a repair of these rules by a model (Section~\ref{sec:history}).

\paragraph{Review of the theft rules}
The review of the theft rules used in Study~3 was made with generative AI: two independent AI editor sessions checked each extracted rule against its cited passages, and a change was adopted only when both made it, or one made it and the other approved it (\texttt{rule\_review/}; Section~\ref{sec:history}). No jurist has reviewed the rules.

\paragraph{Synthetic case texts}
The case texts of \texttt{fresh/}, \texttt{dev\_probe/} and \texttt{fresh2/} were written by generative models that are not among the evaluated ones. The texts of \texttt{fresh2/} were written by Claude Opus 5.5, working as an agent in this repository, from the design briefs; no evaluated model read or wrote any of these data before the test. Their blind check used a different model of the same family, \texttt{claude-fable-5-2}, in four separate Claude Code Remote sessions and one more for a re-read. The messages of \texttt{fresh/} were written by \texttt{anthropic/\allowbreak{}claude-haiku-5.5}, and its blind check used the same model in a fresh context. The 16 probe claims of \texttt{dev\_probe/} were written by Claude in an agent session, by hand in the build script, without any model call. The original study records that the synthetic claims of both Study~1 data sets were created with the assistance of generative AI, including the translation of the German tenancy claims; the Study~1 theft pairs are assembled from their story paragraphs and condition sentences by script, without model calls.
