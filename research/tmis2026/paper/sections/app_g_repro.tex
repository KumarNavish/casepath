\subsection{Reproducing the results without model calls}
\label{app:release-reproduce}

One command re-checks the stored results from a clone, after the product commit has been fetched (\texttt{RELEASE.md}, section~3):
\begin{lstlisting}
PYTHON=<venv>/bin/python research/tmis2026/reproduce.sh
\end{lstlisting}
It makes no model call and writes nothing into the checkout; in a fresh clone without the cache archive it passed 59 steps and skipped 2 in about eleven minutes (\texttt{RELEASE.md}, section~8). It checks the data manifests and rebuilds the probe; checks that the product commit prints the recorded parity hash, and checks the claims of Appendix~\ref{app:proofs} with the product's own evaluator at that commit (\texttt{analysis/\allowbreak{}check\_fragment.py}); re-runs Study~3's pre-registered analysis (\texttt{analysis/\allowbreak{}study3.py}), the post-hoc analysis and the number macros, and compares each with the stored file byte for byte; builds the Study~3 figures without comparing them; runs the analysis tests; and re-runs the analyses of Studies 1 and 2 from their stored checklists and Study~1's response cache, comparing every regenerated evidence file and number macro byte for byte. It does not re-check the model runs themselves, whose stored outputs are its inputs, nor a few inputs that the Study~1--2 re-analysis takes as given (the rule verification, the reference re-derivation, the cluster jobs' exact decision tables and part of the error attribution), nor the Study~1--2 figures.

The analyses added after review are a step of this command. It re-runs \texttt{analysis/\allowbreak{}study3\_\allowbreak{}review.py} into a temporary folder and compares its output with the stored \texttt{analysis/\allowbreak{}study3\_\allowbreak{}review.json} and \texttt{.md}; it then compares the regenerated review macros with the stored file byte for byte and builds Figure~\ref{fig:families}. Two parts of the analysis read Study~3's response cache: the individual readings behind the fact-level accuracy (R3) and the cost split by component (R7). Without the cache archive the step compares everything else, entry by entry and section by section, and reports these two parts as skipped; with the archive in place it compares both files byte for byte.

\paragraph{Re-running Study 3 with model calls}
\texttt{harness/\allowbreak{}study3/\allowbreak{}run\_all.py} re-runs Study~3 (\texttt{harness/\allowbreak{}study3/\allowbreak{}README.md}). It first checks that the plan is committed unmodified, that the product is at the tested commit with the expected parity hash and settings, that the tenancy templates have the recorded hash, and that the converted workflows agree with the reference engines. A re-run needs the reader's own model endpoint and key: the harness's model clients were written for the original container and must be adapted to read a key from the environment, and two scripts still use absolute paths of that container (\texttt{RELEASE.md}, section~4). Without the cache archive every call is made again, and the answers can differ from the stored ones because the models are not deterministic. If the two evaluated model endpoints are retired, only the re-check from stored outputs remains.

\paragraph{Cost}
The ledgers record each model call of Study~3 with its cost: USD~\sthreeSpendTotal{} for the run, \sthreeSpendLuna{} on the cost-efficient model and \sthreeSpendTerra{} on the frontier model (Appendix~\ref{app:dev-study3}). The run log does not record all of this spend and is not the source of these figures. The cost of each design per case is given in Section~\ref{sec:test}.

\subsection{What is not released, and why}
\label{app:release-not}

The insurer's process catalogue, its Knowledge and its case files are not released: they belong to the insurer, and the case files are real claims. The expert study's records will leave the insurer only as the protocol's pseudonymous export, which holds identifiers, statuses, counts, relative times and randomised labels, and no case content (Appendix~\ref{app:protocol}). Its content export, with item texts, notes and the passages behind the insurer's requests, stays with the insurer. Model credentials are not stored anywhere in the repository.

\subsection{Use of generative AI}
\label{app:genai}

\paragraph{Models as objects of study}
The two evaluated models (Section~\ref{sec:test}) are the objects of study: they read the files inside \casepath and answer in every other design. Study~1 also re-scored the recorded predictions of the model of the original study. In the original study a language model extracted the theft rules and their conditions from the source passages, and the theft references derive from a contract built by an agent; Study~2 tested a repair of these rules by a model (Section~\ref{sec:history}).

\paragraph{Review of the theft rules}
The review of the theft rules used in Study~3 was made by two independent AI editor sessions, each checking every extracted rule against its cited passages; a change was adopted only when both made it, or one made it and the other approved it (\texttt{rule\_review/}; Section~\ref{sec:history}). The review files name the editors A and B but do not record which model each session used. No jurist has reviewed the rules.

\paragraph{Who wrote the test texts}
The texts of \texttt{fresh2/} were written by an AI agent session working in the repository, from a brief that contained only the data design. The session had read access to the repository, including the product's prompts and development results; it was instructed to consult no design output, and it implemented no product change. The blind check ran in separate sessions of another model of the same family, without access to the repository. Data writing and product development were directed by the same author, through separate agent sessions. The risk is that knowledge of the product shaped the texts in ways that favour it; the separation of sessions and the instruction reduce this risk but cannot exclude it. No evaluated model read or wrote any of these data before the test. The writing and checking models are named in \texttt{fresh2/\allowbreak{}MANIFEST.json}. The messages of \texttt{fresh/} were written by a third model of that family, which also made their blind check in a fresh context. The 16 probe claims were written by an agent session by hand in the build script, without any model call. The original study records that the synthetic claims of both Study~1 data sets were created with the assistance of generative AI, including the translation of the German tenancy claims; the Study~1 theft pairs are assembled by script from story paragraphs and condition sentences, without model calls.

\paragraph{Assistance to the authors}
AI coding and writing assistants were used, under the authors' direction, to implement the harness and the product changes, to run the analyses, to write the synthetic data as described above, and to draft and edit the text. The authors reviewed all code, results and text and are responsible for them.
