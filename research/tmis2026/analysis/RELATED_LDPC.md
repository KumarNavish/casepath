# Related work: LDPC (Erwin et al., arXiv 2501.11335v1, 2025), read in full

1. **What it does.** "Logical Decomposition for Policy Compliance": a sentence-embedding filter (all-MiniLM-L12-v2, cosine threshold 0.25) returns "Irrelevant"; an LLM with 20 in-context examples splits the policy text into yes/no questions; a RoBERTa-large model fine-tuned on MNLI and ShARC NLI answers each question from the user scenario (entails / contradiction / neutral = True / False / Maybe; answers in the chat history are used as given); an LLM writes a Python boolean formula over the question ids (3 samples, self-consistency by logical equivalence); code evaluates it in Kleene's strong three-valued logic, and Maybe yields a follow-up question.
2. **Benchmarks.** ShARC (end-to-end conversational machine reading: Yes / No / Irrelevant / follow-up question) for the full pipeline; QA4PC's 193 hand-annotated expression trees for choosing the model (logic formulation given the questions: about 92 % for Llama 3 70B, about 85 % for Llama 3 8B; decomposition plus formulation: about 40–45 %).
3. **Models.** Tested: Llama 3 8B and 70B Instruct, CodeLlama 34B, Mixtral 8x7B Instruct; the pipeline uses Llama 3 70B. No task-specific fine-tuning of the decomposition and formula steps; the question-answering model is fine-tuned.
4. **ShARC numbers (Tables 2 and 3).** Dev: micro 79.0, macro 79.7, BLEU-1 57.0, BLEU-4 43.9. Test: micro 70.2, macro 72.8, BLEU-1 46.9, BLEU-4 23.3 (best listed, BiAE: test micro 77.9, macro 81.1). The text gives the dev macro as 79.9 in one place; Table 2 says 79.7. Error analysis of 160 of 470 dev errors: logic formulation 29 %, question answering 28 %, decomposition 19 %, relevance 5 %; 36 % judged borderline cases that could be considered correct.
5. **How CasePath differs.** LDPC has the model write the logic from the policy text per item and answers conditions with an NLI classifier without quotations; CasePath executes the organisation's own rules as written in code, so the logic is not generated, and the model judges each condition as true, false or unresolved with a quotation from the file, and an unresolved condition defers exactly the decisions that depend on it (a document request or a question to the handler) rather than producing one follow-up question for a single-turn dialogue answer.
