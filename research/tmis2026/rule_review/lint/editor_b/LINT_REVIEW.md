# Lint review of flagged conditions (editor B)

- **Starting point:** `rule_review/final/reviewed_rules.json` (99 rules).
- **Input:** `analysis/rule_lint.md`, which flags 15 conditions. Each is used by exactly one rule in the starting file.
- **Output:** `reviewed_rules.json` (99 rules) and `changes.json`.
- **Validator:** `python3 bundle/validate.py lint/editor_b/reviewed_rules.json` reports VALID. Its diff is against `bundle/rules.json`, so it lists the 13 lines from the earlier review as well as the 20 lines from this review.

Each decision rests on the cited passages alone. The readers' quotations were not used as evidence.

**Totals:** U = 9, N = 2, K = 4.

## How the changes were applied

- **U.** The `condition` is set to `null`. `confirming_evidence` is also set to `null`, because its only role was to confirm the removed condition. This follows the starting file, where every rule without a condition has `confirming_evidence: null`. The routes in the facts are unchanged, so those documents are now due in every case. The documents that only the confirming evidence named are still requested by other rules: D01/D02 by 001, D07 by 002, and D03 by 008 and 094.
- **N.** `guard_id` is kept and only `text` is edited. This follows the schema and the earlier review's 042, where the loader derives `<guard_id>.rev-<hash>`. The condition's `cited` list gains the passages that justify the new text. The confirming evidence keeps its routes; its `must_show` and `cited` are aligned with the new text, following the earlier review's 030.
- **K.** No change.

## Points for a jurist

1. **002 (U).** The duty to notify the police applies on every theft for every cited insurer. Under CSS, however, the police report itself is something that "kann durch die CSS einverlangt werden" (0043). Should D07 be requested on every theft, or for CSS only on request? This repeats the earlier review-queue item 002.
2. **003 (N).** VVG 0156 and CSS 0148 restrict the duty to changes "welche die Feststellung der Schadensursache oder des Schadens erschweren oder vereiteln könnte". Simpego 0096 and Generali 0033 forbid any change. Should the condition be limited to changes that could hinder establishing the cause or amount of the loss? Do mitigation measures, such as repairing a forced door, need D26 or D27 at all, given the exceptions? This repeats earlier item 003.
3. **004 (U).** Is the insurer's instruction (D25) due when no mitigation measure is possible after a completed theft? CSS 0170 and Simpego 0100 require only following instructions that were given, while VVG 0116 requires obtaining them. Earlier item 004 (perpetrator and recovery measures) is no longer an issue, because the workflow covers theft only.
4. **008 (K).** The condition "at home" uses a term the passages themselves define as the policy-listed locations ("zu Hause, d.h. an den in der Police aufgeführten Standorten"). Read strictly, the condition assumes the very fact the rule is meant to test. Should it be restated as "the claim is made under the home cover (theft at the claimant's dwelling or premises), not theft away from home"? Alternatively, should the location be checked against the policy on every household-theft claim, which would make this a U?
5. **014 (N).** Is the claim form's printed "bitte Originalkaufbelege beilegen" (0176) a "Verlangen" in the sense of the AVB (0048/0134)? If not, the second limb of the new condition should be dropped. Does VVG 0109 ("deren Beschaffung ihm ohne erhebliche Kosten möglich ist") limit which vouchers may be demanded? This repeats earlier item 014.
6. **042 (K).** Is the unidentified thief "ein Dritter" whose fault caused the loss (Generali 0165)? Can CSS claims "gegenüber Dritten" be "geltend gemacht" (0055) against a perpetrator who has not been identified? If not, the condition should say "an identified third party". If so, D15 is due on every theft paid by CSS or Generali.
7. **073 (K).** Which CSS cover does clause 26's list item "Diebstahl (ohne einfachen Diebstahl)" belong to? The condition should name that cover as a fact checkable in the claim file, for example the specific additional cover or location. Without this, the condition cannot be checked.
8. **Insurer scope (general).** Rules 057 and 061 (CSS passages only) are now unconditional. So are 002 and 004, whose conditions never named an insurer, so making them unconditional does not change their insurer scope. Whether CSS-only rules should carry an "insurer is CSS" condition was outside this lint and was left unchanged.
