# Cost model for planning (stored ledgers only)

Generated by `rebuild/plan/cost_model.py` from stored ledgers, run results and response caches. No model was called and nothing was spent. Every number below is reproducible with `python3 rebuild/plan/cost_model.py`.

## Ledger fields used

product and benchmark ledgers: key, case, run, arm, input_tokens (includes cached), cached_tokens, output_tokens, usd. v2 and fair-prompt ledgers: key, tag.case, tag.method, tag.exp, run, prompt_tokens (includes cached), cached_tokens, completion_tokens (includes reasoning_tokens), reasoning_tokens, cost, latency_s, error.

Cost per file is the sum of the `usd` (or `cost`) field of the file's paid calls. For the product, the file's stored list of call keys is joined to the ledger whoever paid the call (as analysis/study3.py does), so a call answered from the cache in one arm still counts at what it cost when first paid. Other designs: the ledger rows of the design's tag or arm, one per key, grouped by (case, run). The Study 3 means reproduce the stored cost table exactly (19 of 19 design × regime cells equal).

## 4. Adaptive re-reading: what the first reading alone would have given

Per deciding fact read (the routing fact excluded): is the first reading a quoted value (true/false, or an enum value answered true, whose quote occurs in the file text after case and whitespace normalization)? Admitted = the product's stored fact after three readings (status established, verdict accepted). Readings 2 and 3 are the later reading groups of the same run. Without the evaluator's gold, 'wrong' can only mean 'against what three readings gave'.
