## Assumptions and limits

- Per-file prices are the cost model's (see COST_MODEL.md): the core fitted on 173 benchmark files of 183-575 words, 0-4 attachments; medium and long files are extrapolations (the core's calls x per-call tokens grow linearly with words).
- One estimator for all regimes: per-regime differences in the stored files are not carried into the sealed test.
- Catalogue sweep: the core adds one routing-sized call; prompts carry 3x or 4x one regime's rule text (12,194 tokens), beyond any measured prompt.
- Rule change: each baseline reruns the 160 short files per regime; the core reads the added fact three times in a third of them, each reading priced as one benchmark first-reading call (whole file in the prompt).
- Frontier ReAct and self-consistency were never run: ReAct = cost-efficient tokens at frontier prices; self-consistency = the core's cost per file.
- Prefix caching as measured in the stored runs; without it single prompts cost several times more.
- Repeated runs priced as fresh runs (no cache reuse).
