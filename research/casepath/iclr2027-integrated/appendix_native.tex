\section{Correspondence between the two studies}
\label{app:correspondence}
\input{table_full_correspondence.tex}

Both implementations take a source specification, assess case state, plan
evidence, replace the state when observations change and derive a justified
next action. They differ in knowledge, algorithms, estimands and validation.
Study~A uses \path{casepath.theft-method-freeze/5.0.0}, interpreter V4 and
evidence overlay V3. Study~B uses the compact native producer with
\texttt{obligation\_control\_v1} and \texttt{evidence\_demand\_v1}.
Its public template union does not transfer the theft source pack, and
Study~A's theft pairs are not transformations of the native claim roster.

V5 evaluates local guards, projects all mapped routes for active rules,
adds mapped confirmation evidence for true but unconfirmed guards and
subtracts held document types. It has no capability-specific or joint
adequacy assessment. The native controller separates applicability from
acquisition permission and unknown evidence from missing evidence, and
selects a route for each capability. The studies make no performance
comparison between these runtimes.

Study~A's preparation used model calls to extract propositions, synthesise
and refine rules, and map capabilities. The source-only corrections remain
in the record, and the held-out cost excludes this preparation. Study~B's
compilation is deterministic and shared by every arm.

\section{Study B: native metrics and analysis contract}
\label{app:native-metrics}

\paragraph{Endpoints.}
Native critical-evidence recall measures criticality-weighted coverage of
active evidence obligations through a complete permitted document
alternative. Evidence-obligation completeness also requires valid relations
from the decision through the fact and capability to the document.
Valid-chain precision is the fraction of requested items with such a chain.
It is one for an empty request set, so it must be read alongside coverage.

The native contracts define wrong-branch and premature requests, document
states, node and edge scores, branch and path probes, and source locators.
Locator agreement does not establish semantic entailment; probe accuracy
does not directly measure the accuracy of inferred case predicates.
The emitted endpoint counts unique immediate request identities without
using the reference scenario to activate candidate conditions. It is
available only when the reference supplies a unique allowed document set
for each active obligation, complete and consistent document states, and
the public label mapping.

For predicted and reference sets $P,G$, checklist
$F_1=2|P\cap G|/(|P|+|G|)$ and unnecessary fraction
$U=|P\setminus G|/|P|$. When both sets are empty, $F_1$ is one. Empty
predictions receive precision one and burden zero; an empty reference
receives recall one. Failed cells instead receive the frozen adverse unit
penalties: zero for higher-is-better rates and one for lower-is-better
rates. Unavailable reference labels cannot be substituted with empty sets
or used to reduce a denominator.

\paragraph{Weights and contrasts.}
For either a split or the complete corpus, scheduled case $i$ receives
weight $\omega_i=1/(3\,m_{d(i)}\,n_{f(i)})$, where $m_d$ is the number of
families in its domain and $n_f$ is the number of scheduled cases in its
family. Conventional differences use unit scores with adverse imputations.
Conservative benefit-oriented differences contribute $-1$ whenever either
producer endpoint is unobserved. The report also deletes each family in
turn and renormalises the remaining weights within the affected domain.
The resulting ranges measure sensitivity to corpus composition, without
providing confidence intervals.

A comparator counts as beaten only if all three conservative contrasts
strictly exceed their boundaries over the complete protected population,
using the original references and integrity checks. Otherwise the report
records the outcome as not met, a partial practical signal or not evaluable.

\paragraph{Recorded outcomes and failures.}
Each cell records the arm, case and state, followed by either a validated
artefact or the provider output and validation failure. An unknown relation
endpoint references a node absent from the candidate artefact. A truncated
or non-terminal completion reaches the \nbTokens-token limit or ends
without a terminal outcome. An invalid codebook index fails to resolve in
the shared public codebook. A contradictory presence state marks a document
as both present and absent, or as present with an inconsistent state. A
blocked dependency occurs when a control's \casepath source cell fails.
Charges remain attached to every failure, and a repaired version cannot
replace a failed cell in the frozen comparison.

\section{Retrospective request-only diagnostic}
\label{app:request-diagnostic}

The registered wrapper scores emitted requests only after a native receipt
passes evaluation. The shared expression-namespace mismatch therefore
prevents it from scoring any generated request list. The retrospective
diagnostic changes this availability rule alone. It reads the unchanged
\texttt{request\_mode=now} items, maps labels through the original public
mapping and applies the original emitted-set scorer. It does not evaluate
candidate conditions against reference states. The original artefacts,
producer and native failures, primary penalties and costs remain available
separately.

All \nbClaims{} references provide an eligible unique document set.
The \nrRequestObserved{} generated lists receive observed request-only
scores. The \nrRequestPenalties{} failed or blocked outputs retain the
original adverse checklist penalties; no requests are imputed. The original
weights for domains, families and cases remain in force. For benefit
direction $b_m\in\{-1,1\}$, the conventional paired contribution is
$b_m(s_{i,\mathrm{CP},m}-s_{i,a,m})$. The conservative contribution uses
this value when both request-only endpoints are observed and $-1$ otherwise.
A native graph failure does not make a separately scoreable request list
unobserved. This diagnostic applies no practical threshold, significance
test or confidence interval.

\paragraph{Condition names and their meanings.}
The public compiler introduces \nrNativeSymbols{} condition symbols used
by all arms; every emitted symbol belongs to that namespace. The native
expression language evaluates them against the contract's scenario, which
does not supply the required assignment. A target-blind authored
counterexample shows why filling this gap requires a semantic choice.
For an absent condition, the product controller returns unresolved while
the native parser raises a missing-variable error. Substituting null makes
the native Boolean evaluation false, whereas the controller still returns
unresolved. Renaming a symbol, supplying a default or injecting a predicted
state would change its meaning without an explicit state correspondence.
The request-only diagnostic makes none of these changes.

\paragraph{Custody and release.}
The primary scoring task authenticates both complete prediction inventories
before it reads references. The original producer ended without its complete
I/O audit, leaving historical non-access to protected targets unestablished.
Scoring, the compatibility diagnosis and the request-only analysis have
separate records that preserve the original failures. All original target
containers were then released as exact bytes under the recorded data
license. The released version is a public benchmark and cannot provide a
new hidden confirmation.

\paragraph{Offline reproduction.}
The anonymous artifact contains all \nbCells{} prediction and failure
cells, the exact \nbClaims{} reference containers, original native evaluator,
reporting code, source commitments and request-only wrapper. Offline replay
reproduces both primary phase reports, the full primary report, every
request-only row and the descriptive report with exact canonical JSON
equality. It rescores saved outputs without numerical tolerance; it does
not regenerate them or include the remote model checkpoint.

\section{Retrospective evaluation at the assessed state}
\label{app:assessed-state}

\paragraph{The evaluated object.}
The assessed-state interface evaluates each original condition against the
complete three-valued assessment saved with its prediction. Known-active
entities enter a current-case snapshot; unresolved entities remain recorded
but inactive. Counterfactual branch predicates are omitted, excluding
branch-probe accuracy and full-program acceptance. The envelope preserves
the original artefact, assessment and every activation decision. Predicted
activation uses no reference state; native reference graphs, scoring
functions and entity matchers are unchanged.

Negation swaps true and false. Conjunction is true when all children are
true and false when any is false; disjunction uses the dual rules.
Each control keeps its own graph and requests, bound to its saved
\casepath assessment. All \asAllCpN{} compiled-equivalent snapshots and
scores match \casepath, and no immediate request is filtered out.
The release includes the derivatives, identity checks and execution receipts.

\paragraph{Metrics and interpretation.}
Native valid-chain precision counts active requested documents with a
reference-aligned decision, fact, capability and document chain as a fraction
of all active requests. Critical-evidence recall weights covered reference
facts by criticality; obligation completeness counts obligations with valid
matching chains. Unnecessary fraction counts requests absent from the
reference requirements. Here, valid-chain and necessary documents coincide, making
precision and unnecessary fraction complementary. Critical-evidence recall
also equals obligation completeness. These are not independent confirmations.
Exact-source entailment remains unestablished: provenance-chain inheritance
is zero, and omitting predicates makes all-object source support unavailable.
