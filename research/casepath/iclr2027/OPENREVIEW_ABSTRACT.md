# Title

Does the Benchmark Require the Input? A Falsification Audit for Agent Evaluation

# Abstract

Agent benchmarks are often read causally: a high score is taken as evidence that a system used the current task, plan, graph, or tool state correctly. We test a prior requirement for that interpretation: does the evaluation require the input at all, and is the output paired to the right input? We combine established shortcut diagnostics into a pre-interpretation audit: an out-of-group no-input predictor, a wrong-pairing permutation, and evaluator-provenance checks when references are model-generated. The individual tests are not new; the contribution is an executable admission test for input-conditioned claims and an empirical failure case in which a benchmark deliberately redesigned to escape one shortcut preserves it at a deeper level. On two source-grounded workflow scopes, a scenario-cross-fitted predictor that never receives the case achieves release-set micro-F1 0.919 and 0.589, versus 0.459 and 0.078 for the best measured agents. Reassigning agent outputs to the wrong cases leaves those scores essentially unchanged. As a public positive control, the same audit on BFCL Multiple behaves oppositely: Gemini 3.8 Flash scores 0.960 with the query, 0.000 when the query is removed, and 0.0049 on average under wrong pairings. A separate evaluator study shows another information-loss mode: Claude Opus 5 agrees with the original evaluator on only 45.5% of latent decision statuses but produces identical scored document sets on all 58 units. These results distinguish benchmark shortcuts, system output collapse, and scoring-projection collapse, and motivate a simple rule: falsify input dependence before attributing an agent score to input-conditioned competence.
