\begin{abstract}
Agent benchmarks are often read causally: a high score is taken as evidence that a system used the current task, plan, graph, or tool state correctly. We test a prior requirement for that interpretation: \emph{does the evaluation require the input at all, and is the output paired to the right input?} We combine established shortcut diagnostics into a pre-interpretation audit: an out-of-group no-input predictor, a wrong-pairing permutation, and evaluator-provenance checks when references are model-generated. The individual tests are not new; the contribution is an executable admission test for input-conditioned claims and an empirical failure case in which a benchmark deliberately redesigned to escape one shortcut preserves it at a deeper level. On two source-grounded workflow scopes, a scenario-cross-fitted predictor that never receives the case achieves release-set micro-F1 0.919 and 0.589, versus 0.459 and 0.078 for the best measured agents. Reassigning agent outputs to the wrong cases leaves those scores essentially unchanged. As a public positive control, the same audit on BFCL Multiple behaves oppositely: Gemini 3.8 Flash scores 0.960 with the query, 0.000 when the query is removed, and 0.0049 on average under wrong pairings. A separate evaluator study shows another information-loss mode: Claude Opus 5 agrees with the original evaluator on only 45.5\% of latent decision statuses but produces identical scored document sets on all 58 units. These results distinguish benchmark shortcuts, system output collapse, and scoring-projection collapse, and motivate a simple rule: falsify input dependence before attributing an agent score to input-conditioned competence.
\end{abstract}

\section{Introduction}
A benchmark score is routinely interpreted as evidence about a system: a model understood a request, an agent used its tools, or an explicit representation improved reasoning on the current instance. That interpretation has a falsifiable prerequisite. The score must depend on the information that the claim says the system used.

This prerequisite is easy to violate. Partial-input baselines expose tasks solvable from annotation artifacts or one side of the input \citep{kaushik2018reading,poliak2018hypothesis,gururangan2018artifacts}; HANS shows that strong NLI systems can succeed for the wrong syntactic reasons \citep{mccoy2019hans}; simple heuristics expose reading-comprehension questions that do not demand the intended reasoning \citep{sugawara2018easier}. More broadly, benchmark design has long been criticized for failing to identify the capabilities attributed to scores \citep{bowman2021benchmarking,thomas2026validity,joshi2026guardians}. Structured-agent evaluation adds another layer: plans, graphs, tools, model-generated judges, and set-valued outputs can all compress or confound the information being measured.

We encountered this problem while building \casepath, a source-grounded workflow agent. Its first benchmark was static: predict which documents a case requires. We discovered that every measured case in each of two scopes had the same gold checklist. We therefore redesigned the benchmark as paired interventions: add a fact that settles one branch and score which requirements are retracted. The redesign was intended specifically to remove the constant level that broke the static task. It did not. A case-independent release-set predictor still outperforms every measured agent, and shuffling agent outputs onto the wrong cases barely changes their scores.

The paper asks a narrower and more general question than whether \casepath works: \emph{what must be true before an agent benchmark score can support an input-conditioned capability claim?} We use two simple gaps. The \textbf{input gap} compares the evaluated system with a cross-fitted predictor that is denied the evaluation input. The \textbf{pairing gap} compares the observed score with the score after outputs are assigned to the wrong targets within the same inference group. If the first is non-positive, the task can be solved at least as well without the claimed input. If the second is near zero, the evaluated outputs do not demonstrate instance-specific alignment to the targets. Neither test proves construct validity when it passes; either can falsify an input-conditioned interpretation when it fails.

Three findings matter. First, the paired CasePath task fails both tests on two separately authored scopes under a symmetric release-set score. Second, a public tool-use positive control behaves in the opposite direction: on the 200-item BFCL Multiple split \citep{patil2025bfcl}, the same model loses essentially all AST accuracy when its user query is removed, and output permutations destroy its score. A separately pinned diagnostic on API-Bank's released ToolSearcher sample layer \citep{li2023apibank} shows the complementary failure mode: in all 17 evaluable multi-candidate transcripts, the API actually called later is already at candidate position 1. We treat this as a warning about that small released sample layer, not as a benchmark-wide result. Third, evaluator agreement at the scored-output level can conceal large disagreement in latent process state: one independent model family reproduces all final document sets while disagreeing with nearly half of the underlying decision statuses.

We do \emph{not} claim that input ablations or permutations are novel statistical tools. The contribution is to make them an explicit admission test for agent-evaluation claims, to show why a seemingly stronger paired design can inherit the shortcut it was built to escape, and to release an end-to-end negative record in which apparently significant results are withdrawn after the audit.

\section{Related Work}
\paragraph{Shortcuts and partial-input baselines.}
Hypothesis-only, passage-only, and heuristic baselines establish the core diagnostic principle: remove information the task is claimed to require and see what remains \citep{kaushik2018reading,poliak2018hypothesis,gururangan2018artifacts,mccoy2019hans}. \citet{sugawara2018easier} similarly use simple heuristics to separate easy reading-comprehension questions from ones that require richer reasoning. Shortcut learning generalizes the issue beyond NLP \citep{geirhos2020shortcut}, and recent work finds that scale does not eliminate shortcuts in LLMs \citep{yuan2024shortcut}. We extend the diagnostic to a dynamic set-valued agent task and, importantly, cross-fit the no-input predictor so its policy is learned without the held-out group's labels.

\paragraph{Benchmark validity.}
\citet{bowman2021benchmarking} argue that benchmark performance should imply the in-domain capability the benchmark purports to measure. \citet{thomas2026validity} formalize related concerns as evaluation validity, while \citet{joshi2026guardians} show that representation metrics can produce false conclusions when their structural assumptions fail. Our audit is intentionally operational rather than a new theory of validity: it tries to falsify one concrete interpretation---that a score measures response to the current input---before model differences are interpreted.

\paragraph{Evaluator dependence.}
Model-generated evaluators can favor related model families; \citet{li2026preference} call one such effect preference leakage. We had exactly this confound: the original reference adjudicator belonged to a family also evaluated as an interpreter. We therefore repeat reference construction with independent model families. The result does not validate the labels; instead, it reveals that the final scoring projection can be far more stable than the underlying adjudicated state.

\paragraph{Agent and tool-use benchmarks.}
BFCL evaluates function/tool calling across simple, multiple, parallel, and agentic settings \citep{patil2025bfcl}; API-Bank evaluates planning, tool retrieval, and API calling \citep{li2023apibank}. We use BFCL's 200-item V4 Multiple split only as a positive control for our audit, not as an official leaderboard submission: we keep BFCL's published data, possible answers, and AST checker fixed, but run one fixed model through a JSON function-call prompt so that the only experimental difference is whether the user query is present. We also inspect API-Bank's small released level-2 ToolSearcher sample directory as a bounded external diagnostic; its scope is reported explicitly in the appendix.

\section{An Input-Dependence Audit}
Let a benchmark contain grouped instances $(x_i,y_i)$, an evaluated system output $\hat y_i$, and score $S(\hat y,y)$. We define two descriptive gaps; classical confidence intervals are not required for the admission decision.

\subsection{Input gap}
Choose a predeclared class of predictors that cannot access $x_i$. Fit the strongest member on all groups except one and evaluate it on the held-out group; repeat over groups. Let $c_{-g}$ be the policy learned without group $g$. The cross-fitted no-input score is
\begin{equation}
S_{\rm noinput}=S\bigl(c_{-g(i)},y_i\bigr),
\end{equation}
and the input gap is $G_{\rm input}=S(\hat y,y)-S_{\rm noinput}$. A non-positive gap is sufficient to reject the claim that the score demonstrates useful dependence on the current input.

For CasePath the predicted object is the release set itself and $S$ is micro-F1. On each training fold, the constant set maximizing training micro-F1 is obtained by sorting document frequencies and choosing the prefix length with the highest training micro-F1. For exact-match sensitivity we separately use the modal training release set. These are simple empirical-risk-minimizing baselines, not methodological novelties.

For BFCL the stronger ablation preserves each item's candidate function schemas but removes only the user query. The model can therefore still exploit tool names, descriptions, parameter schemas, and item-specific candidate sets; it is denied precisely the information whose use the function-calling score is meant to establish.

\subsection{Pairing gap}
Hold all system outputs fixed and randomly reassign complete outputs across targets, preserving the highest-level grouping used for inference when groups exist. Define
\begin{equation}
G_{\rm pair}=S(\hat y,y)-\mathbb{E}_{\pi}\,S(\hat y_{\pi(i)},y_i).
\end{equation}
A small gap does not by itself prove that the \emph{benchmark} is degenerate; it diagnoses that the evaluated outputs do not demonstrate instance-specific pairing to the targets. In combination with a strong no-input predictor, it separates target regularity from system output collapse.

\subsection{Evaluator projection}
When a learned evaluator produces a latent state $z_i$ that is deterministically mapped to the scored target $y_i=g(z_i)$, agreement on $y$ need not imply agreement on $z$. We therefore report evaluator identity and both latent-state and scored-output agreement. This is a provenance/measurement check, not a claim that agreement among model families substitutes for expert ground truth.

\section{CasePath: A Paired Redesign That Still Does Not Require the Case}
\subsection{System and benchmark}
\casepath maps versioned primary-law passages to gated propositions, a process graph, active obligations, required facts, evidence capabilities, and document routes. Branch predicates are interpreted against a case and the final checklist is compiled deterministically from active nodes. A document is released when no active node still requires it. The mechanics motivate a natural dynamic claim: an explicit process should support coherent requirement retraction when a new fact settles a branch.

The case corpus is synthetic: 150 generated Swiss-tenancy intake claims, not real claimant data. We evaluate two separately authored scopes. Rent increase contributes 28 complete held-out orig/intervention pairs over six scenarios; termination contributes 49 pairs over eight scenarios. The static reference checklist has exactly one observed value in 30 rent-increase originals and one in 49 termination originals, yielding a case-ignoring static F1 of 1.000 in both scopes. This static failure motivated the paired redesign.

The paired target is the set of documents required before but not after the branch-settling addition. Rent increase has three distinct observed release sets; termination has four. We compare direct checklist prediction (B1), graph-as-context prediction (B3), and the compiled induced graph (B5). All policies are now compared on the same predicted object---the release set---using ordinary micro-F1 and exact match. The earlier volume-corrected metric is retained only as historical context in Appendix~\ref{app:history}.

\subsection{A case-independent predictor is stronger on the same score}
Table~\ref{tab:core} reports the symmetric comparison. For rent increase, the scenario-cross-fitted no-input release predictor reaches micro-F1 0.919; the strongest agent reaches 0.459. Its exact-match rate is 0.643 versus 0.071 for the best agent. For termination, the micro-F1-optimized no-input predictor reaches 0.589 versus 0.078. Under exact match, a separately cross-fitted modal release set reaches 0.551 versus 0.531 for the best agent. The conclusion therefore does not depend on the historical volume normalization or on comparing policies with different request-set sizes.

One rent scenario contains generated narratives of roughly 167k characters whose intervention is beyond the historical evaluator's 9,200-character cut. \subsection{The agent outputs barely know which case they belong to}
Using the same release-set micro-F1, B5 scores 0.459 on rent increase while the mean within-scenario wrong-pairing score is 0.458 (permutation $p=0.74$). B3 on termination scores 0.078 while its wrong-pairing mean is 0.061 ($p=0.32$); B5 is identically zero under both. These coarse $p$-values are not treated as classical inference from six or eight clusters. The descriptive point is that incorrect case-to-output pairings reproduce almost all of the apparent performance.

\section{A Public Positive Control: BFCL Requires Its Query}
A falsification audit should not reject every benchmark. We therefore freeze an external control on BFCL V4 Multiple \citep{patil2025bfcl}: 200 public items, each presenting multiple candidate functions and exactly one gold call. The exact BFCL data, possible-answer file, and AST checker are pinned to public commit \texttt{6ea5797}. Gemini 3.8 Flash is run once per item in two matched conditions at temperature zero. The full condition receives the official user query and function schemas. The ablation receives identical schemas but replaces only the query with a removal marker. Parse failures count as incorrect and are not semantically retried. This is a prompt-mode positive control, not an official BFCL leaderboard score.

\section{Evaluator Robustness Can Hide State Disagreement}
The original rent-increase reference used GPT-5.6 Terra, which also appears among the interpreter models. Before inspecting new judgments we froze a robustness study using Claude Opus 5, Gemini 3.1 Pro, and DeepSeek V4 Pro, three temperature-zero calls per 58 narratives. Missingness rules and the family-balanced consensus rule were committed while calls were running but before judgment content was inspected; we therefore call this a prospectively frozen robustness study with pre-inspection amendments, not an immutable preregistration.

Claude Opus 5 is the load-bearing sensitivity because it has 58/58 unit coverage and zero failed calls. It agrees with the original reference on every final document set and all 28 paired release sets. Yet it agrees on only 45.5\% of the 696 individual decision-status comparisons. The deterministic mapping from latent decisions to document unions therefore erases extensive semantic disagreement. High scored-output agreement is not evidence that evaluators agree on the process state the score appears to summarize.

Gemini and DeepSeek are secondary because their semantic-output missingness is substantial. Gemini adjudicates 51/58 units, DeepSeek 50/58, and the prospectively defined three-family complete-case consensus retains 43 units and 17 complete pairs. Missingness is visibly non-random by scenario; for example the consensus retains zero S4 pairs and one of four S8 pairs. We report these results in Appendix~\ref{app:evaluator} rather than use them as the primary robustness claim. The full-coverage Opus result is sufficient to show projection coarsening; it does not establish human label validity.

\section{What the Audit Admits and What It Does Not}
The three checks play different roles. A cross-fitted no-input baseline tests whether target regularity can explain the score without the claimed input. A pairing test asks whether the evaluated system outputs align to the correct instances rather than merely expressing a standing habit. Evaluator provenance asks whether the scored projection conceals instability in the state from which it is derived. We recommend reporting these before attributing a structured-agent score to input-conditioned competence.

The audit is deliberately asymmetric. Passing does not prove construct validity: BFCL's large gaps show only that this model's score strongly depends on the user query and correct item pairing, not that BFCL captures every aspect of real tool competence. Failing is more decisive. If a cross-fitted no-input policy beats the evaluated systems on the same predicted object, the score cannot establish that those systems use the input better than the shortcut. If wrong pairings retain the score, the evaluated outputs do not demonstrate case-specific alignment.

None of the individual operations is novel. The methodological contribution is packaging them as a claim-admission procedure for agent evaluation, applying them symmetrically to a failed dynamic benchmark and a public positive control, and preserving the full sequence by which apparently favorable results were invalidated rather than retrospectively cleaning the record.

\section{Limitations}
The CasePath evidence is narrow: two synthetic scopes in one legal domain generated by one corpus process. It does not establish that legal-document or agent benchmarks generally have this failure. The BFCL experiment is one public benchmark category and one prompt-mode model; it demonstrates specificity of the audit, not broad external prevalence. The API-Bank diagnostic covers only 17 evaluable multi-candidate transcripts from a released sample directory and must not be read as an estimate of API-Bank's full benchmark behavior. A larger benchmark survey would be needed to establish prevalence.

The CasePath validity audit was motivated after observing positive-looking held-out results. We therefore make no confirmatory claim about the underlying agent. Scenario counts are small (six and eight), so bootstrap and permutation values are descriptive; the main conclusions use large deterministic score gaps and cross-fitting rather than calibrated asymptotic uncertainty. The rent reference also contains a known long-input truncation defect, which is why we report whole-scenario exclusion sensitivity.

The independent evaluator study uses models, not expert human annotators. Opus's full-coverage agreement shows that same-family leakage is not needed to reproduce the final document targets, but it does not validate those targets. Finally, historical model runs did not preserve a complete transport-retry ledger, although final per-unit outputs, runner hashes, model identities, prompts, and all current analysis artifacts are committed and hash-bound.

\section{Conclusion}
We redesigned a benchmark because its static task could be solved without reading the case, then discovered that the paired dynamic replacement preserved the same problem in a less obvious form. On two scopes, cross-fitted no-input release predictors outperform the measured agents on the same micro-F1 and exact-match objects, while wrong pairings preserve almost all agent performance. A public BFCL control behaves in the opposite direction: removing the query or breaking the pairing destroys the score. A small API-Bank sample audit independently surfaces a candidate-order shortcut, showing that the same admission test can also flag an external released sample layer. The lesson is not that structured agents fail; it is that benchmark scores should not be attributed to input-conditioned reasoning before input dependence is demonstrated. Remove the input, break the pairing, record evaluator provenance, and only then interpret the score.

\section{Historical Result and Why It Was Demoted}
\label{app:history}
The original paired analysis used withdrawal recall and then a within-arm random-drop correction for request volume. Under the corrected exact expectation, compiled B5 on rent increase has excess $+0.118$, direct B1 $-0.060$, and graph-then-list B3 $+0.011$. The raw B5--B1 withdrawal-recall difference was $+0.553$. Four interpreter runs of the same B5 artifact ranged from $+0.118$ (GPT-5.6 Terra) and $+0.108$ (Gemini 2.5 Flash) to $-0.036$ (DeepSeek v3.2) and $-0.078$ (Claude Haiku 4.5).

We no longer use these cross-policy excess values as the validity headline. The correction is conditional on each policy's own request set and withdrawal count, so it is useful for diagnosing volume within a policy but is not a clean common-scale comparison across policies with different request sets. The main paper therefore scores every policy directly on the same release-set object. The interpreter table remains useful only as a record that a frozen representation plus different interpreters can induce different standing document habits.

\section{Evaluator Robustness and Missingness}
\label{app:evaluator}
The robustness run made 522 physical calls (three families $\times$ three repeats $\times$ 58 units), with reported provider cost \$24.47. Claude Opus 5 had zero failed calls and adjudicated all 58 units. Gemini had 32 failed/unparseable calls and reached the predeclared $\ge2/3$ unit rule on 51 units; DeepSeek had 37 failures and reached it on 50. The three-family complete-case consensus retained 43 units and 17 pairs.

The missingness audit confirms that the consensus subset is not representative enough to carry the main claim. It retains 0/4 S4 pairs, 4/5 S5, 3/5 S6, 4/5 S7, 1/4 S8, and 5/5 S9. Gemini's excluded units are much longer on average because three long S8 units fail, while DeepSeek's exclusions are mostly short S4 units. This is why the main text uses the full-coverage Opus sensitivity and treats the family consensus only as secondary.

On its available units, DeepSeek agrees with the original evaluator on 92\% of final document sets and 81.8\% of release sets; Gemini agrees on 100\% of both on its complete subsets. The three-family consensus agrees on 100\% of final document and release sets on its complete cases. These are projection-stability results, not independent proof that the latent adjudications are correct.

\section{BFCL Positive-Control Protocol}
The BFCL V4 Multiple slice, possible-answer file, and AST checker are copied verbatim from public Gorilla commit \texttt{6ea57973c7a6097fd7c5915698c54c17c5b1b6c8}; their SHA-256 hashes are recorded in \texttt{external/bfcl/SOURCE.json}. The model is \texttt{google/gemini-3.8-flash}, temperature 0, 900 output-token cap, 200 items per condition. Both conditions receive identical function schemas and output instructions; only the official user query is replaced in the ablated condition. The copied BFCL AST checker passes a 200/200 self-test against a schema-aware concrete representative of the official possible-answer encoding.

An initial transport attempt produced 400 OpenRouter HTTP 404 routing rejections because the endpoint selector used \texttt{google}; none reached a provider, used tokens, or incurred cost. Those responses are preserved. The only repair changed the endpoint selector to \texttt{google-ai-studio}, with model, prompts, conditions, scoring and analyses unchanged. The successful 400 semantic calls cost \$0.876567 as reported by the provider. Full-query responses parse 200/200; query-removed responses parse 63/200. Parse failures score incorrect.

\section{Bounded External Negative Diagnostic: API-Bank Samples}
\label{app:apibank}
API-Bank \citep{li2023apibank} releases a small \texttt{level-2-toolsearcher} sample directory containing complete transcripts. We audit only the candidate ordering returned by \texttt{ToolSearcher}; this is not the full API-Bank evaluation set. For each transcript we derive the target from the non-authentication API that is actually called after \texttt{ToolSearcher}, not from the filename. We retain only samples with at least two returned candidates and with that downstream-called API present in the returned list. Seventeen transcripts meet these conditions; 33 are excluded with an explicit reason in \texttt{APIBANK\_PUBLIC\_CONTROL.json}.

In all 17 evaluable transcripts, the downstream-called API is candidate position 1. A query-blind rule that always selects position 1 therefore scores 17/17, while a lexical query-to-candidate selector scores 16/17. This is a deterministic candidate-order shortcut in the released sample layer. Because the subset is small, filtered by explicit eligibility conditions, and not the benchmark's full evaluation corpus, we make no claim about API-Bank's overall reported scores. The value of the diagnostic is narrower: the same no-input audit that CasePath fails and BFCL Multiple passes can expose a shortcut in a public tool-retrieval sample without any model inference.

\section{Corrections Preserved in the Scientific Record}
The repository preserves several errors because they constrain what can be claimed. A structural-impossibility argument was wrong because it pooled document supply across cases while the compiler recomputes it per case. A cross-scope quote-failure analysis confused unmapped source/quote lists with fabrication and was retracted. A contaminated rent-increase bucket contained termination cases and its saturation statistics were withdrawn. An amendment to the original primary comparison rested on development behavior that no longer reproduces exactly. An early volume baseline used 300 Monte Carlo draws and was replaced with the exact hypergeometric expectation.
