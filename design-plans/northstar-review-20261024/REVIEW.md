## Product decisions

The view follows the original north-star reference: white canvas, Mulish, wine accent, a 75px header, 262px source rail, five review roles, persistent process graph and an original-source reader. On narrow screens the panel provides the shared scroll surface.

The Process builder exposes the existing edit forms and an Add step action. A preview keeps the graph and source visible, names newly proposed prerequisites from the actual impact, and distinguishes material process changes from wording changes. An unassessed claim exposes its single existing Review claim control in the default pane.

Result checker shows the exact saved version, passages belonging to the receiving claim, the accepted application and the current evaluation. Historical effects are labelled When applied. A current active requires connection is described as a prerequisite; other current blockers receive neutral blocker wording. A later edit cannot make an old effect appear current.

The selected review role is claim-scoped and survives reload. Source DOM, selected PDF page and settled source focus survive a compatible accepted refresh. Desktop pane scroll is restored to the destination pane; the north-star compact breakpoint matches CSS at 760px.

## Authority and recovery

The presentation module owns no mutation authority. Existing server previews, expected revision and state identity, preview hashes, idempotency keys, accepted event receipts and canonical reloads remain the acceptance path.

Delayed previews are bound to the initiating claim, revision and visit. An obsolete preview cannot publish, redraw or take focus in another visit.

A save that finishes after the same claim has been reopened settles through the live binding using a read-only refresh. It does not replay its POST or inherit the earlier visit's navigation. Busy state remains held through settlement.

Detail, causal process and loop refresh publish together. A failed prerequisite read retains the coherent prior view. A later same-visit revision cannot be overwritten by an older response. A subsequent dependent-read failure renders a context-bound recovery view.

The original intake assessment, source files and evidence reviews remain separate from the adopted working graph. Process completion does not authorise a claim decision.
